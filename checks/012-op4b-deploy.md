## 原版 op_4b（0x4b，handler 0x415e36）逐行破译
```
args: [person, x, y, dir, slot]（0x8000=无效参数返 5）
① 0x4183f7(4) 取 person → 0x418dd0(0x492f90, pid) 查 GS 在场单位表
② 单位不存在（[ecx]==0xffff）→ 什么都不做（返回 1）
③ 单位存在且 [ecx+8]&3==0（在场非隐藏）→ 直接写记录：
     +4=x, +5=y, +8=slot位|dir位（0x449b27 dir→flags；尾参0xffff→0）
   —— 是「设置坐标+朝向」，不是隐藏登记！
```

## 我们此前的错误与后果
- 旧实现把 op_4b 一律 `state=1, x=-1, y=-1`（隐藏等 unit_op_4c 现身）
- S_00 恰好有 `unit_op_4c[0,0,0]` 现身姜维 → 侥幸正确
- **S_01 等 47 章没有姜维的 4c 现身 op**（姜维由 allies 表 65535 空位+出阵名单入场，op_4b 只负责挪位）→ 我方 op_4b 把他隐藏后永不现身 → **主将开局隐形，部队无法行动**
- 扫描数据：op_4b 使用 58 章、person 分布 0..14 各 48-62 次；「姜维 op_4b 但无 4c 现身」的章共 **47 章**

## 修复
1. **engine.js op_4b**：在场单位（state===2）→ 清旧格、落新格（被占则 findFreeCellNear）、设 dir、发 refresh；不在场 → 保留 hidden 创建（S_00 型剧本兼容）
2. **main.js startBattle 兜底条件**：`!battle.sideUnits.length` → `!battle.sideUnits.some(u => u.pid === 0)`（原版主将姜维恒在场；allies 空位 65535 由出阵名单填充，我们跳过空位后需保证姜维必入场）
